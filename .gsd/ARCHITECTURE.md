## 1. System Overview

**COLLMAN Address Verification** is an enterprise-grade internal Employee Address Verification and Background Verification (BGV) platform built for Collman Services. The platform automates and audits physical and residential address authenticity through a unified employee verification wizard, anti-fraud photo evidence validation, GPS geo-coordinate distance computation, multi-language Indian document OCR, and an HR/BGV administrative review portal with role-based access control.

## 2. Architectural Components

### 2.1 Backend Layer (`server/`)
- **Main Server Entry (`server/index.js`)**: Express server initialization, uncaught exception shields, global rate limiting, static directory binding for uploads/downloads, frontend static asset fallback for production build, local and network LAN IP discovery.
- **Database Engine (`server/db/`)**:
  - `database.js`: SQLite connection pool, promisified query helpers (`run`, `get`, `all`, `exec`), and automatic incremental column migrations.
  - `schema.sql`: Authoritative relational DDL enforcing foreign keys, indexes, and constraints.
  - `seed.js`: Initial system roles, super-admin account, sample branches, and departments.
- **API Routing (`server/routes/`)**:
  - `auth.js`: User login, password verification (bcrypt), JWT issuance, session validation.
  - `verify.js`: Employee self-service endpoints: ID lookup, progress save/restore, GPS capture, photo validation & upload, address proof upload, OCR parsing, final declaration submission.
  - `employees.js`: HR employee master management, single creation/editing, bulk Excel upload, geocoding queue management.
  - `queue.js`: Review queue retrieval, case filtering, reviewer assignment, status tallying.
  - `review.js`: Case decisioning (Approve, Reject, Request Information, Mark Reverification), reviewer remarks, audit timeline logging.
  - `roles.js`: Dynamic role definitions, badge colors, and permission assignment.
  - `users.js`: Internal staff user accounts, role association, branch/manager assignment.
  - `masters.js`: CRUD management for Branches, Locations, Departments, Designations, Document Types, and Failure Reasons.
  - `reports.js`: Generation and download of verification dossiers and analytics.
  - `downloadArea.js`: Unified internal staging store for all generated PDFs and Excel exports.
  - `audit.js`: System audit log query and filtering.
- **Middleware (`server/middleware/`)**:
  - `auth.js`: JWT token verification and RBAC permission enforcement.
  - `rateLimiter.js`: Express rate limiting against API abuse.
  - `upload.js`: Multer storage engine handling photo evidence and document uploads with size limits and sanitization.
- **Utility Engines (`server/utils/`)**:
  - `imageValidator.js`: Server-side photo validation mirroring client-side quality and content rules.
  - `geoUtils.js`: Distance calculation (Haversine formula), accuracy threshold analysis, geofence categorization.
  - `geocodingQueue.js`: Background geocoding processor supporting OpenStreetMap / Nominatim with Google Maps fallback.
  - `indianLanguageOcr.js`: OCR text normalization supporting Hindi, Kannada, Malayalam, Tamil, Telugu, and English.
  - `addressProofValidator.js` & `documentAddressMatcher.js`: Fuzzy address and PIN code matching between OCR text and HR records.
  - `pdfGenerator.js`: PDFKit-powered generation of branded, multi-page BGV reports with side-by-side photo grids and comparison maps.
  - `permissions.js`: Permission catalog and evaluation helpers.

## 3. Data Flow Architecture

### 3.1 Employee Verification Flow
```
1. Access /verify -> Enter Emp ID & Mobile/DOB -> Server checks employees table
2. Server issues session token -> Fetches existing progress from verification_progress table
3. Steps 1-5 (Details, Address, Residence) -> Auto-saved to verification_progress
4. Step 6 (Location) -> Browser Geolocation API -> Coordinates saved
5. Steps 7-11 (Photos) -> Web camera capture -> Client imageValidator scans quality/content
   -> If valid, uploaded to /api/verify/photo-evidence -> Server validates & stores in verification_evidence
6. Step 12 (Address Proof) -> Upload front/back -> Client Tesseract.js runs OCR -> Field comparison
7. Step 13 (Declaration) -> Submit -> Status updated to 'Pending BGV Review' -> Case recorded in verification_cases
```

### 3.2 BGV Case Review & Decisioning Flow
```
1. Reviewer logs in at /admin/login -> Server validates credentials, returns JWT with role permissions
2. Reviewer navigates to VerificationQueue -> Selects case -> Opens CaseReview
3. Frontend renders:
   - HR Master Address vs Submitted Address
   - Photo Evidence Grid (Selfie, Door, Street, House, Landmark)
   - Interactive GeoComparisonMap (HR Coordinates vs Verified GPS Coordinates)
   - Address Proof Document + OCR Extracted Text Match Score
4. Reviewer submits decision (Approve / Reject / Reverification / More Info)
5. Server writes to:
   - verification_cases (final_decision, status, reviewed_by, reviewed_at)
   - verification_attempts (attempt record closure)
   - employees (verification_status update)
   - verification_timeline & audit_logs (audit entry)
   - download_area_files (triggers automated PDF dossier generation)
```

## 4. Key Architectural Patterns & Conventions

- **Separation of Concerns**: Decoupled client (Vite/React) and server (Node/Express) architecture.
- **Strict Automated Evidence Validation**: Fail-closed photo quality and content detection preventing spoofing and low-quality evidence; manual overrides intentionally disabled.
- **Persistent Progress Engine**: Verification state preserved step-by-step in `verification_progress` so employees can resume without data loss.
- **Multi-Attempt Lifecycle**: `verification_cases` tracks overall case state while `verification_attempts` and `verification_timeline` preserve historical records across reverifications.
- **Role-Based Access Control (RBAC)**: Granular permission flags (`view_dashboard`, `review_cases`, `manage_roles`, etc.) checked both on client navigation and backend API endpoints.
- **Centralized Download Staging**: All generated artifacts (PDFs, Excel sheets) are cataloged in `download_area_files` before physical retrieval.

## 5. Technical Debt & Observations

- **Large Component Files**: Several frontend components (`CaseReview.jsx` ~131KB, `RoleManagement.jsx` ~101KB, `MastersManagement.jsx` ~97KB) and backend routes (`verify.js` ~75KB, `masters.js` ~47KB) contain combined UI, state, and business logic that could benefit from modular sub-components and service layer abstraction.
- **Dual OCR Engine Execution**: Tesseract.js is bundled on both client (`client/package.json`) and backend (`server/package.json`), along with offline trained data models in the root directory.
- **Database Scalability**: SQLite is currently utilized via local file locking. For scaled multi-instance deployments, transitioning to PostgreSQL would provide concurrent write advantages.
